====================================================================
 0. 产品定位与取舍原则（先定这个，后面全靠它做决定）
====================================================================

0.1 一句话定位
    一个以 AI 角色扮演（AIrp）为核心的自托管 AI 聊天软件。
    能直接吃 SillyTavern 生态的角色卡 / 世界书 / 预设 / 对话存档，
    并且往"能演出一部 galgame"的方向做深。

0.2 它是给谁用的
    自用为主。所以：
    - 不对外搞注册 / 社区；不过后来还是做了多用户，已经能给几个朋友用（见第 7 章 M1）；
    - 追求"我想改什么就能改什么"；
    - 数据全在自己硬盘上，换个电脑拷过去就能接着玩。

0.3 五条取舍原则（冲突时按这个排序）
    1) 兼容优先：别人写好的卡、世界书、预设，拿来就能用，不用转换。
       我自己导出的东西，也要能被别人的软件读回去。
    2) 一切可编辑、可回滚：AI 生成的所有东西（总结、状态、世界书条目、
       生成的图）用户都能手动改，改错了能撤销。
    3) 演出是差异化：别的软件做到"聊天"就完了，我要做到"有画面、
       有声音、有选择、有存档"。
    4) 省钱：能用本地做的（分词、检索、图片、语音）就不调付费模型；
       每轮真正发出去的提示词要能看见、能压缩。
    5) 不黑箱：模型看到的每一句话、花的每一分钱，都要能查到。


====================================================================
 1. 写卡区
====================================================================

1.1 它要解决什么
    从"脑子里有个角色"到"手里有一张能立刻开演的卡"。
    包括：写设定 → 配世界书 → 调提示词 → 灌记忆底子 → 试演 → 定稿。

1.2 角色卡本体
    [核心] 字段：名字、简介(description)、性格(personality)、场景(scenario)、
           开场白(first_mes)、替代开场白(alternate_greetings)、
           对话示例(mes_example)、作者备注(creator_notes)、
           系统提示(system_prompt)、历史后指令(post_history_instructions)、
           标签(tags)、创作者(creator)、版本(character_version)。
    [核心] 头像：支持 PNG 卡（chara / ccv3 双块）、裸 JSON 卡，
           以及 V1 / V2 / V3 三种规格的读写，未知字段原样保留不能丢。
    [核心] 导入：拖拽 PNG/JSON 进窗口就能导；支持批量导入整个文件夹。
    [重要] 导出：导出成 PNG 卡（能把头像一起带走）或 JSON 卡。
    [重要] 卡的组织：搜索、收藏、自定义标签。
    [重要] 卡版本历史：每次保存留一版，能回滚。改坏了不心疼。

1.3 前端（卡内 HTML/CSS/JS，以及影响全局的外观）
    这一块要分成两层，别混在一起：

    第一层：卡内前端（跟这张卡走，只在这张卡的对话里生效）
    [重要] 卡可以自带一段 HTML/CSS/JS，在对话窗口里渲染出来。
           典型用途：状态栏、好感度条、道具栏、地图、小游戏。
    [重要] 卡内脚本能读写的东西：
           - 本对话的变量（读 / 写 / 监听变化）
           - 角色的变量（跨对话的永久属性）
           - 当前对话的消息列表（只读）
           - 往对话里发一条用户消息 / 触发一次 AI 回复
           - 注册回合事件（AI 说完话之后跑一段自己的逻辑）
    [重要] 安全边界：卡内脚本在一个隔离沙箱里跑，不能碰系统、不能联网、
           不能读你别的角色和别的对话。明面上要有"这张卡带脚本"的提示。
    [加分] 卡内前端可以声明它需要哪些能力（读变量 / 写变量 / 发消息……），
           导入时列出来给你确认。
    [加分] 卡内前端可以有"预览模式"：在写卡区就能看到效果，不用开对话。

    第二层：全局外观（影响整个软件，跟卡无关）
    [重要] 主题系统：亮 / 暗 / 跟随系统；可自定义配色、字体、字号、
           聊天气泡样式、圆角、间距。
    [重要] 布局：单栏 / 双栏（左侧卡列表）/ 手机窄屏自适应；
           面板可以拖宽、可以折叠、可以记住上次的状态。
    [重要] 全局自定义 CSS：（可选）高级用户能写一段 CSS 覆盖所有界面。
    [加分] 全局自定义 JS：（可选）同样放沙箱里，用来做全局小挂件。

1.4 提示词系统（这是写卡区最值钱的部分）
    目标：任何人打开"这轮到底发了什么"都能一眼看懂，并且能逐段改。

    [核心] 分层结构（从外到内）：
           1. 全局系统提示（软件级，所有角色共用）
           2. 角色卡自带的系统提示
           3. 预设（preset）里的提示词队列，可拖拽排序、可开关
           4. 世界书 / 记忆 / 数据银行 注入的内容
           5. 前言后语、作者注、示例对话
           6. 真正的对话历史
           7. 前置词（prefill，接在历史后面，AI 接着写）
    [核心] 每段都要能单独设置：内容、角色(system/user/assistant)、
           插入位置、插入深度、是否启用。
    [核心] 宏：{{char}} {{user}} {{persona}} {{time}} {{random}} 之类，
           自己也能定义新宏。支持条件块（if / else）。
    [核心] 正则脚本：发送前改写、收到后改写、只改显示不改发送，
           支持按深度只在最近几条生效。
    [核心] 提示词 X 光机：每轮真正发出去的完整提示词，原样存一份。
           能查看、能搜索、能按段展开、能看到每段占多少 token。
           这是调试"为什么 AI 表现不对"的唯一手段，必须有。
    [重要] 上下文预算：能看到每段吃了多少 token、一共多少。
    [重要] 裁剪策略：保留最近 N 条 / 保留开头 N 条 / 从中间丢。
    [重要] 预设库：自带几套常用的，能导入导出别人的预设（酒馆格式）。

1.5 前置词 / 后置词
    [核心] 前置词（prefill / 续写引导）：接在对话历史最后，让模型顺着往下写。
           常见用法：逼它直接以角色口吻开口、逼它从一个固定的开头继续。
    [核心] 后置词（suffix）：发在最后面的收尾指令，优先级最高。
           常见用法："只输出对话内容"、"不要重复上文"、"用中文"。
    [重要] 两者都要能按角色 / 按对话分别设置。
    [重要] 跟"继续"按钮配合：点继续时不发假用户消息，而是追加一条引导词。

1.6 世界书
    [核心] 兼容两种存储形状：酒馆导出的世界书，以及角色卡内嵌的世界书。
           两种形状互相转换时字段不能丢。
    [核心] 触发方式之一：自然语言触发（关键词 / 短语）
           - 主关键词、次关键词
           - 四种组合逻辑：任一命中 / 全中 / 排除 / 互斥
           - 大小写敏感、整词匹配、扫描深度（只看最近几条）
           - 常量条目：永远注入
    [核心] 触发方式之二：正则触发
           - 用正则表达式匹配对话内容
           - 支持捕获组引用（把匹配到的内容带进条目正文）
    [重要] 触发方式之三（比酒馆更进一步）：语义触发
           - 用向量判断"这条对话内容跟这条世界书讲的是不是一回事"，
             不需要出现关键词也能命中。
           - 给每个条目一个相似度阈值，可单独调。
           - 三种触发方式可以任意组合：关键词 or 正则 or 语义。
    [重要] 条目字段：内容、优先级(order)、位置（历史前 / 历史后 / 指定深度）、
           概率、粘性(sticky 命中后继续生效几轮)、冷却(cooldown)、
           延迟(delay)、分组、组内权重、是否忽略预算(ignoreBudget)。
    [重要] 可视化：条目列表能搜索、能按分组看、能一键试触发
           （输入一段话，看看会激活哪几条、为什么激活）。
    [重要] 预算：世界书整体占提示词的比例上限，超了就按优先级砍。

1.7 记忆系统（小总结 / 大总结）
    三个层次，别只做一层：

    第一层：原始对话（永远不删，是唯一的事实来源）

    第二层：小总结（场景级 / 段落级）[核心]
      - 范围是"最老的那一段还没被总结过的消息"
      - 总结内容：发生了什么、谁说了什么、场景切换、当前目标
      - 存成一条可编辑的记忆条目，挂在它覆盖的消息区间上
      - 注入方式：在提示词里放一个 [前情提要: ...] 块
      - 编辑或删掉某条总结后，它能被重新生成

    第三层：大总结（章节级 / 长期档案）[重要]
      - 每隔几条小总结，再做一次"总结的总结"
      - 专门保留：人物关系变化、重要设定、伏笔、承诺、未完成的事

    额外的两条线：
    [重要] 结构化档案：把记忆拆成表 —— 人物表（谁、长什么样、什么关系）、
           事件表（何时、何地、发生什么、影响）、物品表、地点表。
           比纯文本总结更好检索，也更省 token（只取相关的那几行）。
    [重要] 记忆的可见性：哪些记忆这轮被发给了模型、为什么被选中，
           在 X 光机里要看得到，能手动踢掉某条。
    [加分] 时间线视图：按时间排的事件流，能跳转到原消息。
    [加分] 记忆热度：太久没被用到的记忆可以自动降权，避免越堆越乱。

1.8 数据库与向量化
    [核心] 一个本地数据库装下所有东西，零外部依赖，能整体备份成一个文件。
    [核心] 要存的对象：角色卡、对话与消息、世界书与条目、记忆与总结、
           人设、预设、正则脚本、素材（图片/音频）、调用记录。
    [重要] 向量化要覆盖四类内容，每类独立开关、独立权重：
           1) 世界书条目
           2) 参考资料（上传的 txt/md/json/csv 之类）
           3) 历史对话（把旧对话捞回来当参考）
           4) 记忆条目
    [重要] 混合检索：关键词检索 + 向量检索一起用，结果融合排序。
           专有名词、人名、生僻词靠关键词，语义相近靠向量。
    [重要] 嵌入模型的来源要能选：跟随聊天模型 / 指定模型 / 本地模型。
           本地能做就本地做，省钱。
    [重要] 增量更新：只给新增内容算向量，改过的重算，没改的不动。
           界面上要显示"已向量化多少条 / 有多少条待处理"。
    [加分] 重排序（rerank）：先粗筛 20 条，再精挑 5 条送进提示词。
    [加分] 向量数据的自检与清理：源文件删了，它的向量也要跟着清掉。

1.9 写卡工具链
    [重要] 卡生成器：给一段设定，让模型写出一张能用的卡草稿。
    [重要] 对话式改卡：跟 AI 说一句「把性格改冷一点」，它直接把字段改掉。
    [重要] 体检：检查人设自相矛盾、称呼不一致、示例对话跑偏、
           token 太长、缺少开场白之类的问题。
    [加分] 翻译：把外文卡和世界书翻成中文，保留字段结构。
           （参考：GalTransl/GalTransl）
    [加分] 卡的仓库管理：一堆卡的时候能按标签、来源、最近使用筛选。
           （参考：Sillyanonymous/SillyTavern-CharacterLibrary、Nya-Foundation/card-forge）

1.10 写卡区还可以加（调研里翻到的、你还没提的）
    - 卡内嵌表情差分包：给角色绑一组表情图，对话里按情绪自动换。
      （参考：Susanoo1337/SillyTavern-Expressions-Script）
    - 卡内嵌 BGM / 音效清单，演出时按场景播放。
    - 剧本大纲：给卡写章节梗概，长线剧情有规划而不是走一步算一步。
      （参考：akira399/dsh-novel-writer）
    - 角色关系图：多个角色之间的亲疏、阵营、敌对关系可视化。
    - 卡的一致性锁定：几个关键设定钉死，AI 改稿时不许动。


====================================================================
 2. 玩卡区
====================================================================

2.1 基础对话
    [核心] 流式输出（一个字一个字往外蹦，不要转圈等到最后）。
    [核心] 重新生成、编辑消息、删除消息、插入消息、复制。
    [核心] 继续（接着上一条写，不新增用户回合）。
    [核心] 扮演（让 AI 替我打一句草稿，填进输入框，我改完再发）。
    [核心] 每条消息显示 token 数；整轮显示花了多少钱。
    [重要] 消息级开关：这条设为系统提示（只展示不发送）、这条隐藏。
    [重要] 多模型快速切换：同一个对话换模型接着聊，不用重开。
    [重要] 多标签/多开：同时开好几个角色的对话，随时切。
    [重要] 全文搜索：在所有对话里搜一句话，定位到具体某轮。
    [重要] 导入导出：酒馆的 JSONL 存档能读能写，双向不丢字段。

2.2 群聊与多角色
    [核心] 一个对话里放多个角色，AI 决定谁开口（自然 / 列表 / 手动 / 混合）。
    [核心] 每个角色的活跃度权重、静音、单独推进。
    [重要] 角色之间互相对话，不只是各自跟我说话。
    [重要] 多角色时的提示词隔离：A 的专属设定不能串给 B。
    [加分] 自动模式：隔几秒让下一个角色自动说一句，我挂着看戏。

2.3 场景状态（把"聊天"变成"玩"）
    [重要] 变量系统：对话变量（本局）、角色变量（跨局永久）。
    [重要] 状态面板：属性、好感度、任务、物品、地点、时间，
           可以用卡内前端画成条、格子、卡片。
    [重要] 状态由 AI 更新：模型每轮末尾输出一段结构化状态改动，
           解析后写进变量；解析失败不影响对话。
    [重要] 状态可手动改：我随时能改好感度、加个道具、跳过任务。
    （参考：SpicyMarinara/rpg-companion-sillytavern、diceframe/diceframe）
    [加分] 骰子 / 检定：需要随机判定时真的掷骰子，结果写进对话。
    [加分] 状态快照与回滚：玩崩了能倒回上一个节点。

2.4 叙事控制
    [重要] 行动选项：每轮给 3-4 个候选行动按钮，点一下就等于我发那句话。
           比让模型调用工具便宜得多，也快得多。
           （参考：flizzywine/dsh-tavern）
    [重要] 分支与存档：任意一条消息都能开一个分支，各分支独立发展。
    [重要] 导演模式：我能以"旁白/作者"身份插话，指定剧情走向、
           让某个角色退场、强制某件事发生。
    [加分] 章节管理：把长对话切成章，每章有标题和摘要。
    [加分] 结局收集：玩到的结局存进一个图鉴。
    [加分] 随机事件：按概率插入小插曲，让剧情不那么平。

2.5 galgame 演出层（这是我要跟别人拉开距离的地方）
    [重要] 立绘层：角色立绘 + 表情差分，按情绪自动切换、有淡入淡出。
    [重要] 背景层：场景背景图，随地点变化自动换。
    [重要] 对话框：底部对话框样式，名字牌，打字机效果，点击继续。
    [重要] 选项分支：三个选项按钮浮在画面上，选完接上后续。
    [加分] BGM / 音效：按场景自动播放，音量可调。
    [加分] 转场效果：黑屏、闪白、震动、镜头平移。
    [加分] CG 回廊：生成过 / 触发过的图收进一个相册。
    [加分] 好感度与路线：好感度到阈值解锁不同剧情线，多结局。
    [加分] 一键导出 Ren'Py 工程：把一条对话线导出成能直接跑的 galgame
           脚本，素材一起打包。（这是很狠的差异化功能，如果做成了，
           等于"用聊天软件写 galgame"这件事闭环了）
    （参考：SlimeBoyOwO/LingChat、Zao-chen/ZcChat、tamikip/AI-GAL、
     SiriLee/Storyloom、GalTransl/GalTransl、vnve/vnve）

2.7 图片生成与素材
    [重要] 立绘、背景、CG 都能生成；生成结果自动入库当素材。
    [重要] 与剧情联动：检测到场景变化 / 出现新角色，提示或自动出图。
    [重要] 图片来源：本地模型（ComfyUI）/ 手动上传。
    [加分] 图片编辑：局部重绘、扩图、换表情差分。
    [加分] 角色一致性：同一个角色反复出图要长得像（固定种子 / 参考图 / 训练）。

2.8 记忆与检索在对话中的表现
    [重要] 每轮自动做的事：扫描最近对话 → 决定激活哪些世界书条目、
           捞哪些旧对话、取哪几条记忆 → 拼进提示词。
    [重要] 我能看见上面这个过程的结果，并且能手动干预（加一条、踢一条）。
    [重要] 上一轮的表现可以复盘：AI 为什么这么答，输入是什么。
    [加分] 对话内搜索"我们之前是不是说过这个"。

3.1 ComfyUI 接入（你说要做的，我拆细一点）
    [核心] 连接方式：填 ComfyUI 地址就能连（本地默认 127.0.0.1:8188），
           也能填远程地址；连不上要给出清楚的原因。
    [核心] 工作流模板：用户在 ComfyUI 里搭好工作流，导出 API 格式的 JSON，
           软件里导入这个 JSON，然后把里面的几个节点标记成"可填参数"。
    [核心] 参数占位符：文本提示词里能写 {{char}}、{{scene}}、{{emotion}}、
           {{user}} 等，软件发请求前替换成当前对话的真实内容。
    [核心] 三种触发方式：
           1) 手动 —— 界面上点一下"出一张图"
           2) 半自动 —— AI 回复里出现特定标记（比如 [IMG: ...]）就出图
           3) 全自动 —— 检测到场景/角色变化就出图
    [核心] 结果入库：生成的图自动存进素材库，跟这条消息绑定，能点开大图。
    [重要] 队列与进度：显示当前排队几个、跑到第几步（ComfyUI 有进度接口）。
    [重要] 预设几个常用工作流：立绘、表情差分、背景、CG、局部重绘。
    [重要] 参数可调：正向/负向提示词、步数、尺寸、随机种子、模型。
           种子要能固定，方便同一角色出一致的图。
    [加分] 表情差分批量出图：一次把"开心/难过/生气/害羞"全出了。
    [加分] 局部重绘：圈一块区域改。
    [加分] 图生图：拿当前立绘当参考图出新姿势。
    [加分] 不同角色绑不同 LoRA / 工作流。
    [加分] 服务没开的时候不要报错崩溃，提示"ComfyUI 未启动"并禁用按钮。

【原清单里两处现在有答案了】
  - 0.2 原来写「不追求多用户、注册、社区」→ 已按实际改写成"自用为主，但支持给朋友用"（见 M1）。

【平台 / 部署】
  M1. 多用户模式（原清单没列）  [核心 · 后加]
      一个网址 + 登录；一个账号 = 一个完整数据目录（各自的 SQLite、素材、主密钥），
      互相看不见。登录按 IP 限速、伪造的 x-forwarded-for 不算数；HTTPS 下 Cookie
      自动 Secure；停用账号 / 改口令立刻踢掉会话。起法：node server/index.mjs --multi-user。
  M2. 主机管理（管理员账号）  [重要 · 后加]
      加人 / 停用 / 重置口令 / 删除（可连数据一起删）；服务总览与租户磁盘占用。
      命令行也能加人查人：--add-user / --list-users / --set-password。
  M3. 加密备份导出 / 导入（.stbk）  [重要 · 后加]
      全量备份可以用口令加密（AES-256-GCM + scrypt），主机管理员也解不开。
      原清单 3.2 只要求"一个压缩包带走所有数据"，没要求加密。
  M4. 单文件 exe（web 资源一起嵌进去）  [加分 · 后加]
      Node SEA + postject 打成一个 exe，双击起服务；同一份 exe 还能当 MCP 服务器（--mcp）。
      原清单只在"自动更新"里提了一句"打包成单个 exe 之后"。
  M5. 一人一实例 / 一人一份 MCP 的部署方式  [重要 · 后加]
      不想要登录那套也行：给每人一个进程 + 各自的 TAVERN_DATA_DIR，放进局域网 / Tailscale；
      MCP 也能 --mcp --user <账号> 直接指向某个租户目录。README「给朋友用」两种部署都写了。

【模型接入（原清单只在 3.2 顺带提了"各家单价"和"缓存"）】
  P1. 提供方注册表 + 能力声明  [重要 · 后加]
      聊天 / 嵌入 / 图片 / 语音合成 / 语音识别五类用途各挂各的提供方，
      一个提供方可以只用于其中一类。
  P2. 密钥加密存储 + 连通性测试 + 查询可用模型  [重要 · 后加]
      API Key 落库前加密（主密钥在数据目录里），列表接口不回明文；
      能"测一下通不通"、能拉提供方的模型清单。
  P3. 多种鉴权与中转站写法  [重要 · 后加]
      自定义请求头 + 七种鉴权写法（bearer / raw / api-key / x-api-key /
      x-goog-api-key / 把 key 放 URL 参数上 / 不要鉴权），公益站与各类中转站都能接；
      Google Vertex（express API key / 服务账号，Gemini 与 Claude 都行）。
  P4. 模型绑定到角色 / 对话 / 群成员  [重要 · 后加]
      除了"全局默认"，还能给某张卡、某条对话、群聊里某个成员单绑模型；
      绑了哪个提供方、用哪个模型，在 X 光机里看得到。原清单 2.1 只要求"换模型接着聊"。
  P5. CLI 渠道：本地代理托管  [重要 · 后加]
      有些模型要走本地命令行（把 CLI 当 OpenAI 兼容网关）。这里能配"启动命令 + 参数 +
      环境变量 + 工作目录"，调用前自动拉起。它以服务进程身份执行命令，
      所以多用户下只给管理员用（见 S2）。
  P6. 适配器家族 + 内置提供方预设  [重要 · 后加]
      六种适配器：OpenAI 兼容 / Azure / Anthropic / Gemini / 文本补全 / Vertex；
      内置 27 个提供方预设（DeepSeek、Kimi、智谱 GLM、硅基流动、Groq、Grok、OpenRouter、
      Mistral、Together，本地 Ollama / LM Studio / llama.cpp / KoboldCpp / vLLM，
      Azure、Vertex Gemini+Claude、通用中转，以及 Claude / Gemini 的 CLI 本地代理、
      三家嵌入模型）。选预设就行，不用手填地址与鉴权。
  P7. 多模型协同（原清单只有"换模型接着聊"）  [核心 · 后加]
      多家提供方同时存在；同一个对话能换模型接着聊；更进一步，按角色 / 群聊成员各绑
      不同模型，几个模型共用同一份记忆、世界书和上下文（A 用 GPT、B 用 Claude 同场演戏）。

【写卡区（1.3 / 1.4 / 1.9 的实现补细化）】
  W1. 写卡助手（Agent）这个形态本身  [重要 · 后加]
      原清单 1.9 讲的是一串工具，实际做成了一个多步 Agent：想一步 → 调一个技能 →
      再想下一步，每一步（思考 / 调用 / 结果）都能看见；同一批技能也能单独点一次跑。
      技能：生成草稿 / 改写字段 / 体检 / 开场白 / 抽世界书 / 打标签 / 翻译 / 压缩。
  W2. 卡内前端的"信任"与静态校验  [重要 · 后加]
      自己的卡直接跑；别人的卡要你点一下"信任这张卡"——信任绑定的是这段代码的指纹，
      代码一改就得重新信任，而且信任记录不随卡导出。越界写法（联网 / 存储 / 动态执行 /
      导航外带数据 / 内联事件 / 提前收尾脚本块）在保存和渲染两处静态拦下。
  W3. 输出后处理的完整正则链  [重要 · 后加]
      AI 的输出先过"全局 → 角色卡 → 预设"的正则，再解析状态块 / 存历史；
      "只改显示"的脚本结果单独进 displayContent，不污染发出去的提示词。
  W4. 一致性锁定的拦截点是三条路  [加分 · 后加]
      原清单 1.10 说"AI 改稿时不许动"；实际是界面 / 写卡助手 / MCP 三个入口都拦。
  W5. 写卡区是一个工作台  [加分 · 后加]
      原清单 1.1 讲的是"写设定 → 配世界书 → 调提示词 → 灌记忆 → 试演 → 定稿"这条流程；
      实际收成一个入口 + 11 个标签页（角色卡 / 编辑器 / 世界书 / 提示词 / 记忆 / 向量 /
      卡内前端 / X 光机 / 工具链 / 写卡助手 / MCP 工具），来回跳不用换页面。

【玩卡区（2.1 的实现补细化）】
  N1. 候选回复（swipes / "再来一版"）  [核心 · 后加]
      一条回复不满意可以"再来一版"追加候选，用 ◀ ▶ 在候选之间来回翻；
      翻到哪一版，后面的对话就从哪一版继续。原清单 2.1 只写了"重新生成"，

  N2. 从卡库选卡开演 + 卡以快照进对话  [重要 · 后加]
      对话可以直接拿卡库里的一张卡开演（自动带简介、开场白，卡内嵌的世界书跟着生效）。
      卡数据是以快照形式存进这条对话的，characterId 只指向卡库——以后改卡不会回改旧对话。

【扩展性（原清单 3.2 这里只有一句话）】

【工具箱 3.1 的实现补细化】
  X1. ComfyUI 两种执行方式（服务器执行 / 浏览器直连）  [重要 · 后加]
      原清单 3.1 只说"填地址就能连"。实际分两种：主机进程出网（单机 / 管理员），
      或由浏览器直连 ComfyUI（多用户默认）。直连时主机不碰你填的地址，
      半自动 / 全自动触发落成"待办"，等你浏览器在线时再执行。
  X2. 出图的可观测与重试 + 参数预览  [加分 · 后加]
      对话气泡里显示出图进度与失败原因，失败能点"重试"；调工作流参数时能先"预览"
      占位符替换后的最终 prompt，再决定要不要真出图；排队中的任务还能取消。

【图片 / 素材（2.7 的实现补细化）】
  A1. 素材按内容哈希去重  [加分 · 后加]
      同一张图传两次只存一份（按内容 sha256）。
  A2. 素材引用计数  [加分 · 后加]
      删除前能看到"消息 / 出图记录 / 角色头像各引用了几次"。
  A3. 素材库页面  [重要 · 后加]
      网格预览、按类型（图片 / 音频 / 视频）筛选、上传、删除；出图结果与对话里的消息
      互相关联。原清单 2.7 只在"图片来源"里提了"手动上传"，没提一个能翻能筛的素材库页。
      一条已有消息也能手动挂素材（把图 / 音频绑到那条消息上）。

【安全 / 运维（原清单没有这一块，属于后加的边界）】
  S1. 破坏性操作二次确认 + 大改动前自动留档  [重要 · 后加]
      删账号 / 恢复备份 / 清理这类操作要确认；启动、恢复前、清理前、批量导入前、
      批量删除前、数据库迁移前各自动留一份备份，保留最近 N 份。
  S2. "让主机替你做事"的入口按角色收口  [重要 · 后加]
      本地代理托管、本地 MCP 服务器、ComfyUI 主机代连，多用户下只有管理员能用；
      成员租户在运行时就不建这些能力（不是靠界面藏起来）。详见 docs/SECURITY.md。
  S3. 工程约束  [说明 · 后加]
      零第三方运行时依赖（只用 Node 内置模块）、前端无构建；AGPL-3.0，从 SillyTavern
      移植 / 改编的文件逐条登记在 NOTICE.md，兼容性一律以 release 分支源码为准。
  S4. 数据库版本化迁移  [说明 · 后加]
      schema 按版本迁移（当前 v1–v10），已经发布过的迁移只增不改；迁移前自动留一份备份。
  S5. 恢复不用重启  [重要 · 后加]
      恢复是把备份里的表整体搬回正在用的库（字段对不上会明确拒绝），不用停服务；
      素材文件按 assets/ 前缀镜像写回，越界条目跳过并计数。
